# B 系 — 大纲结构规则

本文件定义 thesis skill 在 Phase 1（大纲生成）必须遵守的结构规则，以及 outline.md 文件的内容契约。规则编号 B.x 与 `rules-index.md` 一致。

> **范围说明**：本文件不再包含任何排版/字体/字号规则——这些已迁至 `format-rules.md`（E 系），且必须从用户提供的范文/模板抓取，不硬编码。

---

## B.1 一节一论点（hook G 系硬检查）

章节及子节标题**只能表达一个概念**。"X 与 Y / X 和 Y / X 及 Y" 拼接两个不同概念的标题禁止。

### 禁止例
- `2.2 Vue 与 Element Plus`（两个独立技术）
- `4.2.1 用户登录与权限校验流程`（登录与鉴权是两个流程）
- `5.1.3 病虫害知识库与时间轴`（知识库与时间轴是两个子功能）
- `1.1 研究背景与意义`（背景与意义是两个独立论点）

### 允许的例外
仅当连接的是**单一固定词或不可分概念**时允许：
- `系统分析与设计`（仅当章节确实把分析-设计作为统一方法论叙述）
- `前后端分离架构`（"前后端分离"是单一术语）
- `增删改查`（习语固定短语）

判定方法：能否就两半分别写出独立的、有信息量的段落？能 → 是两个论点 → 拆分。

### 改写策略
1. 拆为兄弟节：`1.1 研究背景与意义` → `1.1 研究背景` + `1.2 研究意义`
2. 选主从次：`Vue 与 Element Plus` → `Vue 3 前端框架`（Element Plus 在节内作为生态描述）
3. 上位概念统摄：`采摘记录与成品分级` → `茶叶生产链管理`（仅在上位概念真实存在时）
4. 吸收：`病虫害知识库与时间轴` → `病虫害知识库`（时间轴作为查询视图叙述）

适用范围：所有标题层级，从章到 4 级子节，包括图表标题（见 B.5）。

## B.2 本科论文第 1 章结构（hook G 系硬检查）

本科毕业论文第 1 章（绪论）**严格遵循**：

```
第1章 绪论
  1.1 研究背景
  1.2 研究意义
  1.3 国内外研究现状
    1.3.1 国内研究现状
    1.3.2 国外研究现状
    1.3.3 文献述评
```

**硬约束**：
- `1.3` 必须拆为三个子节：国内 / 国外 / 文献述评，缺一不可
- `1.3.3 文献述评` **必须存在**——作者综合两侧研究、识别 gap、论证本研究必要性的位置
- **不得包含 `1.5 研究内容`**——研究内容在后续章节自然展开，1.5 显式声明是硕士/博士级冗余
- 第 1 章止于 `1.3`（导师特别要求时可附 `1.4 本文组织结构`，非默认）

**硕士/博士论文**：`1.5 研究内容` 与 `1.6 本文组织结构` 允许且常规。论文类型（本科/硕士/博士）记录在 `progress.md → Meta.Type` 字段，决定本规则是否激活。

## B.3 图表预声明（hook G 系硬检查）

每章在 outline.md 中**必须**预声明该章计划的图表。无图表声明的重点章节属不完整大纲。

### 声明格式
每条声明必须包含：
- 序号（图X.Y / 表X.Y，章号与本章一致）
- 图表类型（用例图 / 流程图 / 架构图 / 实体属性图 / 三线表 / 测试用例表 / 折线图 / 柱状图 / 时序图 等）
- 简明标题

### 在 outline.md 中的位置
- 内联在子节后：`[图X.Y 类型 标题]` 或 `[表X.Y 类型 标题]`
- 或章末"图表清单"块统一列出

### 正例
```
第3章 需求分析
  3.1 功能需求分析
    3.1.1 系统管理员用例    [图3.1 用例图 系统管理员功能用例图]
    3.1.2 茶园管理人员用例  [图3.2 用例图 茶园管理人员功能用例图]
  3.2 非功能需求分析
```

### 反例
```
第3章 需求分析
  3.1 功能需求分析
    3.1.1 系统管理员用例    ← 缺图表声明
```

### 重点章节最低图表数（建议，hook 仅检查存在性）
| 章节 | 最低数 |
|------|--------|
| 绪论 | 0（除非研究框架图） |
| 相关技术介绍 | 0–2 |
| 需求分析 | 至少 3（每角色 1 个用例图） |
| 系统设计 | 至少 8（架构图 + 流程图 ≥3 + 实体属性图 ≥4 + 数据库三线表 ≥10） |
| 系统实现 | 至少 6（每个主模块 1 张截图） |
| 系统测试 | 至少 3 张测试用例三线表 |

## B.4 章节字数预算（hook G 系硬检查）

每个主章必须在 outline.md 中以括号声明预估字数，强制规划章节平衡。

格式：`第4章 系统设计（~3500字）`

### 16000 字本科论文典型分配
| 章 | 字数 |
|----|------|
| 第1章 绪论 | ~1500 |
| 第2章 相关技术 | ~1200 |
| 第3章 需求分析 | ~1800 |
| 第4章 系统设计 | ~3500 |
| 第5章 系统实现 | ~4000 |
| 第6章 系统测试 | ~1500 |
| 第7章 总结 | ~800 |

### 字数预算对齐（hook 检查时机）
当章节看似完整时（下一章标题已出现 / 用户标记完成）hook 比对实际字数：
- 实际 < 预算 × 0.7：警告"未写满，差距过大"
- 实际 > 预算 × 1.3：警告"超出预算，请精简"

## B.5 图表标题一节一论点

图表标题与节标题适用同一规则（B.1），不得用"X 与 Y"拼接：

- 禁止：`图4.3 用户登录与权限校验流程图`
- 允许：`图4.3 用户登录流程图` + `图4.4 权限校验流程图`

## B.6 outline.md 内容契约

详细大纲**必须**持久化到 `<project-root>/.thesis/outline.md`，不得只放 progress.md 或对话历史。

### 文件位置
`<project-root>/.thesis/outline.md`

> 旧版规则误写为 `.claude/thesis/outline.md`——CC 对 `.claude/` 目录有硬保护，写入触发 PermissionRequest 即使 bypassPermissions 也无法绕过。已统一改为 `.thesis/`。

### 必须包含
1. Meta：论文类型、目标字数、写作依据（范文路径、开题报告路径、代码库引用）
2. 完整章树 + 每章字数预算（B.4 格式）
3. 每章子节结构
4. 每章图表清单（编号 + 类型 + 标题 + 所属节，见 B.3）
5. 每章关键论点 / 写作策略
6. 参考文献规划（已有 + 待检索）
7. 规则合规自证（B.1-B.5 + A 系 + C 系）

### 禁止包含
- 章节正文（正文在 docx 文件，不在 outline.md）
- 完整参考文献条目（在 docx 末尾参考文献节 + progress.md References）

### 工作流约束
- Phase 1 必须同时建 outline.md 和 progress.md（progress 指向 outline）
- 后续会话写章节前**先重读** outline.md 对应章块，不依赖对话内存
- 大纲变更时同步更新 outline.md，并在 progress.md → User Feedback 记原因

## B.7 输出文件布局

新写论文时项目目录结构：

```
<project-root>/
├── docs/
│   ├── <论文名>.docx              ← 最终交付物（python-docx 直写）
│   └── .backups/
│       └── <论文名>-<时间戳>.docx  ← 修正模式备份（见 E 系 E.4）
└── .thesis/
    ├── progress.md                 ← 索引（状态、总结、反馈）
    └── outline.md                  ← 详细大纲契约
```

**约束**：
1. docx 是论文内容唯一载体（**禁用 markdown 中间文件、禁用 pandoc 转换**）
2. python-docx 程序化设置格式（按 Phase 0 抓取的格式表）
3. docx 文件名 = 论文标题，Phase 1 与用户确认
4. `.thesis/` 仅放 progress.md 和 outline.md
