# E 系 — 格式契约

本文件**不存放任何具体格式数据**（页边距 cm、字号、字体、行距倍数）。

不同学校论文格式不同，硬编码任何"小四宋体 1.5 倍行距 2.5cm 边距"都会在下一所学校失效。E 系只规定"如何获取格式规则"和"如何应用与保持格式一致"。

具体格式数据由 thesis skill 在 Phase 0 / Phase 3 入口从用户提供的范文或模板抓取，写入 `.thesis/format-spec.md` 作为本论文项目的格式契约。

---

## E.1 格式规则来源（HARD-GATE）

<HARD-GATE>
撰写或修正论文时**严禁**使用任何硬编码的学校格式（如"页面 2.5cm"、"小四宋体"、"1.5 倍行距"等）。

每个论文项目的格式必须从**以下两类来源之一**抓取：
1. 用户提供的**学校格式模板**（.docx 模板文件）
2. 用户提供的**范文**（同学校已通过答辩的论文 .docx）
3. 修正模式下用户明确不提供 → **保持原文（待修正 docx）的现有格式**

不允许凭印象 / 凭训练数据 / 凭"通用学术惯例"猜任何具体数值。
</HARD-GATE>

---

## E.2 抓取协议（Phase 0 与 Phase 3 入口）

### E.2.1 Phase 1（新撰写论文）入口

新建论文进入 Phase 1（大纲生成）**之前**必须执行：

```
AskUserQuestion(
  question="论文格式规则的来源？",
  options=[
    "提供学校格式模板（.docx）",
    "提供同学校范文（.docx）",
    "我没有，按通用本科模板生成（thesis skill 用最小默认）"
  ]
)
```

- 选项 1/2：用户提供文件 → thesis skill 用 python-docx 读取该文件 → 抽取格式表 → 写 `.thesis/format-spec.md`
- 选项 3：thesis skill 给出**最小默认**（仅页面 A4 + 三线表三线 + 图题在图下/表题在表上等普世规则），具体字号字体在 `format-spec.md` 中标记 `[默认值，建议用户确认]`

### E.2.2 Phase 3（修正论文）入口

修正论文进入工作前**必须**执行：

```
AskUserQuestion(
  question="修正模式下的格式规则参照？",
  options=[
    "提供学校格式模板（.docx）",
    "提供同学校范文（.docx）",
    "无参照，按修正前的原文格式（保持一致）"
  ]
)
```

- 选项 1/2：抽取格式表 → 写 `.thesis/format-spec.md` → 修正内容应用此格式
- 选项 3：**不抽取任何额外规则**，所有修正内容必须**与原文段落格式一致**（字体、字号、缩进等沿用原文）

### E.2.3 抓取产物：format-spec.md

写入 `<project-root>/.thesis/format-spec.md`，结构如下（字段值由抓取/默认/原文继承填充）：

```markdown
# Format Spec — 格式契约

## 来源
- Source: <"模板"|"范文"|"原文继承"|"默认">
- Source file: <路径>
- Captured at: <日期>

## 页面
- 上下左右边距、装订线、行距、单/双面

## 字体字号映射
- 论文题目 / 各级标题 / 正文 / 摘要 / 关键词 / 图题 / 表题 / 图例 / 参考文献条目 / 致谢 / 页码
- 每条：字体 / 字号 / 加粗 / 对齐 / 缩进

## 段落
- 段前段后 / 行距 / 首行缩进

## 标题编号体系
- 编号格式（1 / 1.1 / 1.1.1 或 第1章 / 1.1）
- 编号与文字间空白
- 加粗规则

## 特殊段落
- 摘要标题中间空字符数
- 关键词分隔符
- 参考文献悬挂缩进

## 备注
- 来源中能直接提取的硬规则 vs 需要用户确认的项
```

## E.3 应用契约

### E.3.1 撰写时（Phase 1/2）
- python-docx 脚本必须**读 `.thesis/format-spec.md`**，按其中字段调用对应 API（`run.font.name`、`run.font.size`、`paragraph.paragraph_format.line_spacing` 等）
- 任何硬编码字号/字体/边距的 python-docx 代码 → **违规**
- 用户提供学校模板 .docx 时优先用 `Document(template_path)` 继承样式而非手设属性

### E.3.2 修正时（Phase 3）
- 修正内容应用 `format-spec.md` 中字段
- 当 `Source = "原文继承"` 时，每段修正前先读该段现有 run 的格式属性（font.name / size / italic / underline 等），**沿用**这些属性写入修正内容

## E.4 修正模式硬规则（HARD-GATE）

<HARD-GATE>
Phase 3（draft revision）**必须**遵守以下 4 条硬规则。任一项缺失 → hook 阻断。

### E.4.1 修正前备份原文
修改 docx 之前**必须**先备份：
```
docs/.backups/<论文名>-<YYYYMMDD-HHMMSS>.docx
```
- 时间戳 = 备份时刻（年月日-时分秒）
- 自动创建 `.backups/` 目录
- 每轮修正生成新备份（不覆盖旧备份）
- hook G.18 检查：本轮修改的 docx 在本次修改时间戳前必须有 `.backups/` 中存在的同名前缀文件

### E.4.2 修正内容用蓝色字体
所有由 thesis skill 修正插入或重写的 run，颜色必须设为 `RGB(0, 0, 255)`（纯蓝）：
```python
from docx.shared import RGBColor
run.font.color.rgb = RGBColor(0x00, 0x00, 0xFF)
```
- 用户视觉上能直接区分原文 vs 修改
- 用户审查后决定接受 / 改回黑色 / 撤回

### E.4.3 禁止改动原文其他位置格式
- 仅可修改：(a) 修正段落的文字内容、(b) 修正 run 的颜色（黑→蓝）
- 不得修改：原文其他段落的字体、字号、对齐、缩进、间距、页眉页脚、目录、页码
- 不得修改：未被修正的段落的颜色

### E.4.4 必须先 AskUserQuestion 询问格式参照
进入 Phase 3 工作前先执行 E.2.2 询问，**不得跳过**。

</HARD-GATE>

## E.5 通用学术普世格式（不依赖学校模板的硬规则）

下列规则跨学校通用，**不需要**抓取，直接生效。这些是中文学术论文的普世底线。

### E.5.1 页面尺寸
- A4 纸（210mm × 297mm，drawio px 等价 827×1169）
- 单/双面打印 → 走 format-spec.md（学校决定）

### E.5.2 三线表
- 见 D.2：仅顶线、栏目线、底线，禁竖线，禁内部其他横线
- 字号字体走 format-spec.md

### E.5.3 图题位置
- 图题在图**下方**居中
- 表题在表**上方**居中
- 标题末**无标点**

### E.5.4 编号
- 图：图1, 图2, ... 按正文顺序
- 表：表1, 表2, ... 按正文顺序
- 章节图表：图3.1, 图3.2, ... 编号含章号

### E.5.5 参考文献分页
- 参考文献**另起一页**
- 致谢、附录各自另起一页

### E.5.6 量纲
- 法定计量单位（GB 3100-1993）：s（秒）、min（分）、h（小时）、d（天）、m / cm / mm、kg / g、°C 等
- 不混用国际制与英制

### E.5.7 章节编号必须用 Word 多级编号（实现强制）

正文中所有章、节、子节的编号**必须**通过 Word 多级编号自动生成，**禁止**在标题文本里手打数字。

#### Why
手打编号在调整章节顺序、增删章节时不会自动更新，导致编号错乱、目录失效。Word 多级编号绑定到 Heading 1/2/3 样式，调整章节时编号自动重排，目录可一键刷新。

#### Word 操作（用户视角）
"开始 → 编号" 下拉 → "多级编号" 区域 → 选与本科论文匹配的模板（如 `1 / 1.1 / 1.1.1` 或 `第一章 / 1.1 / 1.1.1`）→ 自动绑定 Heading 1/2/3 样式。

#### python-docx 实现（写入端）
通过 `docx.oxml` 操作 numbering.xml：
- 新建 `<w:abstractNum>` 定义多级编号格式（每级 `<w:lvl>` 设 `lvlText="%1"`、`"%1.%2"`、`"%1.%2.%3"`）
- 新建 `<w:num>` 关联 abstractNum
- 在每个 heading 段落的 `<w:pPr>` 加 `<w:numPr>` 子元素引用 numId，并设 `<w:ilvl>` 对应级别

#### 禁止的实现
```python
doc.add_heading('1 绪论', level=1)       # 错误：手打 "1"
doc.add_heading('1.1 研究背景', level=2)  # 错误：手打 "1.1"
```

#### 正确的实现
```python
doc.add_heading('绪论', level=1)         # 纯文字标题
doc.add_heading('研究背景', level=2)
# 配合 numbering.xml 的 abstractNum + num + numPr 自动渲染 "1 绪论" / "1.1 研究背景"
```

#### hook 检查（G.21）
扫所有 Heading 1/2/3 段落是否含 `<w:pPr>/<w:numPr>` 子元素。**没有** numPr 即视为手打编号违规。

### E.5.8 参考文献编号必须用 Word 自定义列表（实现强制）

参考文献节中每条文献前的 `[1]` `[2]` `[3]`... **必须**用 Word"项目符号和编号 → 自定义列表 → `[1]/a)/i.`"模板自动生成，**禁止**手打。

#### Why
- 增删/重排参考文献时，自动列表会同步更新所有编号
- 与正文 `[N]` 引用保持一致性靠人工维护极易出错；自动列表保证 `[1]` `[2]` `[3]` 序列连续无跳号
- 用户截图 2 显示的"`[1]/a)/i.`" 是 Word 自定义列表的标准 GB/T 7714 模板

#### Word 操作（用户视角）
选中所有参考文献条目段落 → "开始 → 项目符号 → 自定义列表" → "`[1]/a)/i.`" → 顶层显示 `[1]`、`[2]`、`[3]`...

#### python-docx 实现（写入端）
同 E.5.7，但 `<w:lvl>` 的 `lvlText` 设为 `"[%1]"`，并在每条参考文献段落 `<w:pPr>` 加 `<w:numPr>` 引用该 numId。

#### 禁止的实现
```python
doc.add_paragraph('[1] 刘美琼. 福建茶园生态管理[J]. ...')   # 错误：手打 "[1]"
doc.add_paragraph('[2] 申玲芝. 茶园碳储量评估[J]. ...')
```

#### 正确的实现
```python
para = doc.add_paragraph('刘美琼. 福建茶园生态管理[J]. ...')
para.style = '参考文献'   # 已绑定 numId 的样式
# 列表 numId 自动渲染 "[1]"、"[2]"...
```

#### hook 检查（G.22）
扫 `## 参考文献` 之后的非空段落，检查是否含 `<w:pPr>/<w:numPr>`。**没有** numPr 即手打 `[N]` 违规。

## E.6 实现方式（python-docx）

- E.6.1 通过 python-docx 直接创建和编辑 docx
- E.6.2 **禁用 markdown 中间文件，禁用 pandoc 转换**
- E.6.3 用户提供学校模板时优先 `Document(template_path)` 创建新文档
- E.6.4 无模板时显式设置：从 `format-spec.md` 读字段，逐项设置 run / paragraph / section 属性
- E.6.5 中英文字体分别处理（中文 `<w:rFonts w:eastAsia="...">`，英文 `font.name`）
